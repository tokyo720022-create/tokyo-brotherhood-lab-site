Android guide

Install & update

How to download, install and update the What's Next Android APK, what to try when Android says the package can't be installed, and how to report a problem. APKs from outside the Google Play Store need a little extra care, so please read the safety section first.

1. Before you install

Safety precautions

  • Use official links only. Download from the APK release list on this site or from the project's own GitHub releases. An official download link starts with https://github.com/tokyo720022-create/What-Next/releases/download/. Don't install a file with a similar name that someone sent you in a chat or found on another website.
  • Know what you're installing. Each entry on the release list is labelled Stable release, Pre-release or Debug / testing build. Debug and testing builds are meant for testing and can be less polished. If the list shows no stable release, none has been published yet.
  • Check the checksum if you can. When GitHub provides one, the release list shows a SHA-256 checksum under each APK. After downloading, compare it with the checksum of your file (for example sha256sum file.apk on Linux/macOS or Get-FileHash file.apk in Windows PowerShell). If they differ, delete the file and download it again.
  • Read the release notes before installing, and read the permission prompts Android shows.
  • Protect your AniList login. What's Next logs you in through AniList's own website in your browser. Treat any login token like a password and never share it.
  • Turn permissions back off. Installing outside the Play Store needs the "install unknown apps" permission for the app you used to open the file. You can switch it off again afterwards.
What this guide doesn't state. A minimum Android version, device compatibility list and permission list haven't been published for What's Next, so none are given here. If an install fails or the app misbehaves on your phone, please report your device model and Android version.

2. Download the APK

  1. Open the APK releases page on your Android phone.
  2. Pick a build. Use the search box, build-type filter and sort menu if the list is long, and read the release notes. Some builds reuse the same file name (for example app-debug.apk), so compare the APK uploaded date rather than the file name to tell builds apart.
  3. Tap Download APK. Your browser may warn that this type of file can harm your device. That warning appears for every APK; continue only because you used an official link.
  4. Wait for the download to finish. If it is interrupted, download it again instead of trying to install a partial file.

3. Install it

Menu names differ slightly between Android versions and phone makers, but the normal system prompts look like this.

  1. Open the downloaded file from the browser's download notification, or find it in your Files or Downloads app.
  2. If Android says your phone isn't allowed to install unknown apps from this source, tap Settings and allow it for the app you are using (for example your browser or file manager). Then go back and open the file again. On older Android versions this is a single "Unknown sources" setting.
  3. Tap Install. Google Play Protect may scan the app or show a warning because the app isn't from the Play Store. Read the message and continue only if you trust the source.
  4. When it finishes, tap Open. The app appears as What Next?.
  5. Log in with your AniList account. AniList opens in your browser and returns you to the app after you approve it.

4. Update an installed app

  1. Find your installed version: Settings → Apps → What Next? → App info (the version is usually listed at the bottom).
  2. Open the APK releases page and check whether a newer build exists, using the upload date and release notes.
  3. Before updating, open What's Next while online and let it finish syncing. The app keeps changes made offline on your device until you are back online, so anything still waiting could be lost if the update has to be done another way.
  4. Download the newer APK and open it as described above. Android should offer an Update button because it is the same app.
  5. If Android refuses, see If it can't be installed and Signature mismatches.
About your data. Android normally keeps an app's data when a newer version is installed over it, but this isn't guaranteed, and it does not apply if the old version has to be uninstalled first. Locally stored data, such as your saved login, cached lists and unsynced changes, may be lost in that case. Your AniList account data itself is stored by AniList, not by the app.

5. If it can't be installed

Android may say "App not installed", "There was a problem parsing the package" or that the package conflicts with an existing one. Work through these in order:

  • Download problem. Delete the file and download it again, ideally on a stable connection. Compare the SHA-256 checksum if the release list shows one.
  • Not allowed to install from this source. Allow "install unknown apps" for the browser or file manager you opened the file with (see step 3 above).
  • Not enough storage. Free some space and try again.
  • Conflict with an existing install. If What's Next is already installed, the new file must be signed with the same key. This is the most common cause when updating. See Signature mismatches.
  • Trying to go backwards. Android won't install an older build over a newer one. Use the newest build, or uninstall first (which removes local app data).
  • Blocked by Play Protect or a managed device. Work, school or parental-control profiles can block apps from outside the Play Store. That is a setting on your device, not something the app can change.
  • Still failing? It may be a compatibility problem with your phone or Android version. Report it with the exact message Android showed.

6. Why signature mismatches happen

Every Android APK is signed with a key. To install an update over an existing app, Android requires the new APK to be signed with the same key as the one already installed. If the key is different, Android treats the file as a different publisher's app and refuses to install it as an update, with a message such as "App not installed as package conflicts with an existing package".

This can happen when:

  • Debug builds are signed with a debug key. The project's build script (build-apk.yml in the What-Next repository) builds debug APKs with the Android Gradle task assembleDebug. Android build tools create the debug key automatically on the machine doing the build. If builds are made on different or fresh machines, they can end up with different debug keys.
  • The signing key is changed on purpose. For example, if a future build is signed with a separate release key, it won't update over a debug build, and the other way round.

The release list can't show which key signed a given APK, so there's no way to tell in advance. If you hit a mismatch, the usual fix is to uninstall the existing What's Next app and install the new APK. Uninstalling removes the app's local data, so first open the app online and let any pending changes sync. Afterwards you will need to log in with AniList again.

Something went wrong?

Report an installation error

The best reports are specific. The bug-report button opens a GitHub issue with a ready-made template (a free GitHub account is needed to post). Please include:

  • The APK file name and its upload date from the release list
  • Your device model and Android version (Settings → About phone)
  • The exact message Android showed, or a screenshot
  • What you did, step by step, and what you expected to happen
  • Whether What's Next was already installed, and from which build
